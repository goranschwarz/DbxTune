🤖 LLM/AI Advice

Ask an LLM (Claude, Gemini, ChatGPT, Ollama, ...) how to make a slow SQL statement faster: query rewrites and index changes, based on the statement, its execution plan and the tables it uses.
 
How to get LLM Advice

There is no "ask" box on this page: the advice is always asked for one SQL statement, from the place where you find it. Every place below shows a Get LLM Optimization Advice button, an LLM Optimization Advice section or an LLM Advice link, that opens the advice dialog.

📧 1. Daily Summary Report all DBMS types
  1. Open a report: the mail, or Landing Page → (server) → Daily Summary Report
  2. In the Top SQL / Query Store / slow statement tables, click LLM Advice next to a statement
  3. The advice page opens in a new tab: pick a model, press Get Advice
The report already holds the statement, its plan and the workload numbers (executions, CPU, reads): they are sent along.
📊 2. Execution Plan (Showplan) SQL Server, ASE, Oracle, MySQL, Db2
  1. Open a plan: click a plan in a report or in Active Statements, or Tools → Showplan → (DBMS) and paste one
  2. Expand the LLM Optimization Advice section under the plan
  3. Pick a model, press Get Advice
Pasting a plan yourself: fill in Server and Database too, so the table DDL, indexes and statistics can be looked up. Postgres: the plan page has a Get LLM Optimization Advice button.
⚡ 3. Active Statements live and history
Landing Page → (server), open the Active Statements panel (the button). Then, on a statement's row:
  • Its plan (best): click the checked plan column of the row (for example HasLiveQueryplan on SQL Server) → the Execution Plan dialog opens → expand LLM Optimization Advice (see 2). The column's name depends on the DBMS: see the table below.
  • The row: click anywhere else on the row → the row's details → Get LLM Optimization Advice
Statements from earlier ("go back in time"): see History View below.
📈 4. Counter Details live and history
  1. Landing Page → (server), open the Counter Details of a counter (for example Top SQL, Statement Cache)
  2. Click a row that has a SQL text
  3. Press Get LLM Optimization Advice
The DBMS version of that very sample is sent along.
📋 5. LLM Prompt Preview no LLM needed
Next to each LLM Optimization Advice section there is an LLM Prompt Preview: the exact prompt DbxCentral would send.
  • See what is sent, before anything is sent
  • Copy it into your own LLM chat (ChatGPT, Claude.ai, Copilot, ...) - this also works when no LLM is configured here
🔗 6. Share or look again
Every answer is saved. The link under an answer opens it again: send it to a colleague. Your own saved advice is listed below, under My Saved Advice.

Active Statements from earlier: History View
  1. Pick the day and hours, on the server page's menu bar:
    • the calendar button: choose any period
    • or the 2h buttons: step to the previous/next day or the previous/next hours
  2. Go to the time: click on a graph at that time (for example a CPU peak) - the page switches to History View at that very sample. Or press (History View) and drag the timeline slider that shows under the menu bar
  3. The Active Statements panel now shows the statements of that sample: click the plan column (or the row) as above
  4. Back to live: press (Normal View)
The table information sent to the LLM then describes the tables as they were at that time (the Collector's DDL Storage).
What is sent to the LLM
  • The SQL statement, and its execution plan when there is one
  • The tables it uses: DDL, indexes and statistics (from the Collector's DDL Storage)
  • The DBMS type and version
  • The workload numbers (executions, CPU, reads, ...) when they are known
  • The server's configuration and hardware, when the Collector can be reached:
    • All: the settings that are not at their default, the memory and optimizer settings, the CPU cores and memory (host monitoring gives these where the DBMS can't), and the statement's database (not on Oracle and Db2)
    • SQL Server: also the collation, trace flags and the Resource Governor
    • ASE: also the page size, the memory left to configure, data caches with their buffer pools and bindings, thread pools, resource limits, character set and sort order, trace flags
    • Postgres: also the extensions
    • Oracle: also the block size and character set
    • MySQL: also the SQL mode
    • Db2: also the page size, registry variables, buffer pools and table spaces
The What was sent section under each answer, or the Prompt Preview, shows all of it. The configuration part leaves out paths, addresses and security settings, and an admin can turn it off: DbxCentral.llm.serverContext.
Good to know
  • Nothing is executed in your database: it is advice, test it before you change anything
  • Ask again with another model: the answers are listed on top of each other, to compare
  • Long answers: the model's thinking is shown while it works, Stop cancels the call
  • Each answer costs tokens (shown with each answer, and in the list below)
